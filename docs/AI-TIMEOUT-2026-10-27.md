# 2026-10-27 AI 生成超时诊断与修复

> 历史记录：2026-10-28 用户要求保留 `high`，已改用生成额度与采样参数修复；当前配置和验证见 [保留 high 的修复记录](AI-REASONING-2026-10-28.md)。下文的 `none` 是此前方案。

## 现象与原因

任务 5306 在 17:08:43 入队，17:09:28、17:10:14、17:11:01 连续生成失败；间隔符合 45000 毫秒超时以及 1 秒、2 秒重试退避。只读查询确认该任务为 `failed`，生成 3 次、发送 0 次，输入长 2 个字符，没有已保存的回复，也没有该会话的历史上下文。没有读取或重放原消息正文。

当前本机模型地址为 `http://localhost:1235/v1`，模型配置为 `Qwen3.5-9b`；请求能成功路由至实际加载的 `qwen3.5-9b`。服务连接和模型标识大小写均未造成 HTTP 拒绝。

使用现有系统提示词和独立测试输入“你好”进行限时对比，仅统计耗时及字符数，不记录生成的推理或正文：

| 设置 | 结果 |
| --- | --- |
| 模型默认推理设置 | 65 秒内持续返回推理，共 9182 个推理字符，正文仍为 0；诊断请求到期取消 |
| `reasoning_effort=none` | 约 596 毫秒完成，正文非空、推理为 0 |
| `chat_template_kwargs.enable_thinking=false` | 当前服务未关闭推理；生成到测试 token 上限后正文仍为空，未采用此参数 |
| 修复后的实际非流式 AIClient | 约 487 毫秒取得非空正文；没有发送 QQ 消息 |

因此，本轮故障原因是本机模型在 45 秒内只生成推理，没有完成最终正文。原日志把超时、网络错误、服务拒绝等全部归为 `ai_generation_failed`，无法直接区分原因。

诊断期间检测到 `.env` 的 `AI_TIMEOUT_MS` 已调整为 `100000`，修复保留此值和其他现有配置，仅增加 `AI_REASONING_EFFORT=none`。

## 改动与验证

- 新增可选配置 `AI_REASONING_EFFORT`。留空时不发送额外参数，保持其他模型服务的默认行为；非空时传入 `reasoning_effort`。管理台“AI 与回复”提供同一配置。
- 当前本机模型配置为 `none`，每次机器人请求关闭推理；不修改 LM Studio 的全局设置或系统提示词。
- 生成失败日志增加固定 `reason`、`duration_ms`、`timeout_ms`，HTTP 拒绝时增加 `http_status`。不记录请求正文、API Key、异常原文或模型推理文本。
- 请求取消与超时分别归类，取消不标为可重试。只含推理的返回仍判定失败，绝不把推理当成 QQ 回复。
- 237 项回归全部通过，失败、取消、跳过、待办均为 0；包含新增的参数传递、HTTP 拒绝、响应头/正文超时、取消、推理正文隔离及日志测试。

| 日志 reason | 含义 |
| --- | --- |
| `ai_timeout` | 达到模型请求超时，包含读取正文的时间 |
| `ai_cancelled` | 服务关闭或调用方取消请求 |
| `ai_http_error` | 模型服务返回非成功状态，查看 `http_status` |
| `ai_network_error` | 连接阶段失败 |
| `ai_response_interrupted` | 读取响应正文时连接中断 |
| `ai_reasoning_only` | 返回只有推理，没有可发送的正文 |
| `ai_empty_reply` | 返回没有有效正文 |
| `ai_invalid_json` | 响应不是有效 JSON |
| `ai_response_too_large` | 响应超过 2 MiB 上限 |
| `ai_unknown_error` | 自定义 AI 或其他未分类异常 |

## 生效与回退

这次包含程序代码更新，需要关闭当前启动窗口，再双击项目根目录的 `start.cmd`，重新启动整个 Node 进程。网页“重启生效”在原进程内重建服务实例，不能重新载入已经缓存的 JavaScript 模块。

任务 5306 保持失败状态，没有重新入队或重发。程序重新启动后，可发一条新的测试消息验收实际 QQ 回复。

修改前的文件及 `.env` 备份位于 `dist/ai-generation-fix-backup-20261027`。停止程序后，可从备份恢复同名文件与 `.env`，并移除备份清单中标记为新增的文件；备份含有原配置密钥，请仅保留在本机。

模型服务需支持相应的 `reasoning_effort` 取值，换用其他服务时可在设置中留空。本次采用的 `none` 已在本机服务实测，参数支持可参考 [LM Studio 官方变更记录](https://lmstudio.ai/changelog/lmstudio) 中 0.4.8 的说明。Qwen 模型的推理和最终正文分离见 [Qwen3.5-9B 官方模型说明](https://huggingface.co/Qwen/Qwen3.5-9B)。
