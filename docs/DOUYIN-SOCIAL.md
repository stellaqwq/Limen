# 抖音好友分享与私信

抖音网页插件支持向指定好友分享当前视频、准备私信。普通草稿由管理员在“Agent 管理 → 分享与私信”准备、核对并确认发送；另可启用默认好友自动聊天，以及[自主刷视频与分享](DOUYIN-AUTONOMY.md)。只允许单个好友，不群发；QQ 不获得普通社交草稿和聊天读取工具，开启自主分享后可取得固定默认好友的推荐组合工具。

## 使用

1. 在“抖音网页浏览 → 分享与私信”开启“启用分享与私信草稿”。新安装默认关闭；本次项目配置已开启。
2. 在专用抖音窗口登录。管理页选择“私信”或“分享当前视频”，打开对应面板，再“读取当前联系人”。如果网页结构未识别，请在抖音窗口手动打开面板后重试。
3. 选择明确的好友，填写私信正文或分享留言，点击“保存草稿”；也可在测试对话要求模型“为指定好友准备一份私信草稿”或“准备把当前视频分享给指定好友”。模型不会实际发送。
4. 点击草稿的“准备并核对”。私信会选中好友并填入正文，但不会发送。真实抖音的逐好友直接分享面板在这一步不点击好友行或发送控件。准备成功后显示页面快照，用来核对账号、好友、正文和视频。
5. 点击“确认发送给……”才执行一次发送控件激活。准备令牌仅有效 60 秒，绑定草稿版本；页面、账号、收件人、正文、视频变化时拒绝发送。
6. 点击发送不等于取得抖音送达回执。当前执行层会标为“需在抖音核对”，由管理员查看网站后选择“已送达”或“未送达”。结果未知不自动重试；不能对同一草稿再次点击发送。

取消草稿只撤销本项目的待发资格，不会自动清除抖音编辑器里已填入的文字；需要时请在网页中处理。

私信最多 1,000 字，分享留言可为空。当前实测的抖音好友直接分享面板没有独立留言框，此时应把留言留空；需要附言可另建一份私信草稿。有原输入内容时不会覆盖；输入框已经与同一草稿一致时允许重新准备。

联系人只覆盖当前面板已加载、可确认的好友。找不到目标时可先在抖音面板里手动搜索，再重新读取。不可辨识的联系人、重复身份、群聊及未知类型不会自动选择。

## 默认好友与聊天

在插件“分享与私信”设置中填写 `social_default_friend`，优先用唯一抖音号；也可读取联系人后点击“将所选好友设为默认”。首次精确匹配后绑定真实账号标识，绑定保存在本地 SQLite，重启有效；同名、当前登录账号变化或身份不符时停止。切换默认好友会保留原有草稿的收件人。

本次用户指定的默认好友为 `yirizxc`。此账号昵称为空白字符，通过分享面板的真实抖音号与私信会话的唯一用户标识核对。

在“抖音聊天”开启 `chat_read_enabled` 后，管理页可“打开默认好友会话”“读取最近消息”“生成回复草稿”。只读默认好友当前可见的最近消息，最多20条，不滚动加载全部历史、不下载附件、不写入视频知识库。关闭时不向模型提供读取工具。已有输入文字时不会切走到其他好友。

拟回复任务仅允许打开默认会话、读取消息和创建关联收到消息的私信草稿，不能操作视频、桌面或其他联系人。回复引用有效期5分钟，按消息标识去重；最新消息为自己发出时不再自动拟回复。收到的文字是不可信资料，不能更改权限。聊天内容会送给当前配置的模型用于生成回复。

默认好友省去了每次重复指定收件人。未开启自动聊天时，仍在管理页逐条核对并确认发送。

## 自动聊天

入口：**插件 → 抖音网页浏览 → 编辑 → 抖音聊天 → 自动聊天**。默认关闭；打开并保存表示允许后台自动回复已绑定的默认好友，无需每条再次确认。当前项目配置保持关闭，未额外发送真实测试消息。

前提是插件、允许网页测试对话、分享与私信、聊天读取均启用，默认好友身份已核对，AI 与 Agent 已配置启用，并保持专用抖音浏览器打开、已登录。不会自动启动浏览器或处理登录验证。

- 默认每15秒检查一次，可设10–300秒。没有新消息时不调用模型；每小时默认最多20次，范围1–120。
- 首次开启、重新保存配置、恢复网页控制及服务重启时，将当前消息作为基线，跳过历史；只处理此后收到的默认好友新消息。
- 对方新消息触发受限模型任务，读取上下文并拟回复。后台只发送该任务为同一条收到消息创建的私信草稿，既有手动草稿不会被自动发送。
- 发出前重新核对登录账号、默认好友、正文、配置版本和最新消息 ID。生成期间来了新消息或编辑器已有文字时，放弃旧回复或等待处理；不会覆盖手动输入。
- 一条消息最多处理一次，尝试记录在 SQLite，重启不重放。发送控件只激活一次，随后从当前会话检查相同正文及服务端 ID；这代表网页发送记录，不代表对方已读。草稿保留可人工核对状态。
- 结果未知、验证阻挡、身份变化或模型失败时停止自动处理，不重发。处理问题后重新保存设置可重新建立基线。关闭开关、停用插件或“停止网页操作”会撤销尚未执行的自动发送。

普通自动聊天仍使用受限的拟回复流程，不群发、不执行桌面或其他联系人操作。独立开启“自主刷视频”后，默认好友的新刷视频指令可创建受限浏览任务，通过组合工具向该好友分享和私信，详见[说明](DOUYIN-AUTONOMY.md)。

## 模型工具

- `douyin_social_open`：打开当前视频分享或消息面板；`select_default:true` 可选定默认好友，不发送。
- `douyin_social_inspect`：读取当前账号和联系人元数据，生成短期 `recipient_ref`、当前视频 `source_ref`，不导出聊天正文。
- `douyin_social_draft`：根据实际引用创建草稿；省略 `recipient_ref` 使用默认好友，`reply_to` 引用收到的消息并去重。不发送。
- `douyin_chat_read`：需单独开启，只读取选中的默认好友最近消息，其他好友或群聊拒绝。

普通草稿工具不提供模型可调用的发送、确认令牌接口。自主推荐由执行层内部完成固定收件人的准备与提交，令牌不进入模型结果、列表或明文数据库字段。管理接口使用原有管理员认证和工作台 Origin 检查。

## 页面校验与记录

- 使用精确的 `https://www.douyin.com` 来源及专用标签页。发送前重新检查可见账号身份指纹、唯一收件人、正文、分享视频身份和唯一发送控件。
- 联系人标识来自界面或组件的身份元数据；只读取会话 ID、类型、用户标识等白名单字段，普通联系人检查不读取消息列表，默认好友聊天读取单独校验。单聊/群聊类型的语义参考[官方 IM 类型说明](https://docs.volcengine.com/docs/real_time_communication/TypeDetails-15?lang=zh)，并与本机网页实际结构核对。
- 私信编辑器、会话头、发送图标及好友直接分享面板已按本机实际控件结构适配。网站更新导致无法识别时停止，不猜测坐标或尝试其他发送途径。
- 适配器仅从项目固定的 `social-page.mjs` 加载；更新会撤销已有准备令牌，要求重新核对。不接受模型传入任意选择器或 JavaScript。
- 草稿持久化在 SQLite。状态包括草稿、准备、提交中、需核对、已人工核对送达、已取消；提交中进程退出会恢复为“需核对”，不会补发。已准备草稿在重启后须重新准备。
- 并发发送使用草稿版本和状态进行原子竞争，确认令牌只能使用一次。准备过程中取消不会被后到的准备结果恢复。
- 分享引用当前真实视频身份；当前视频变化时拒绝分享，不会自动跳转到另一个猜测的视频。没有精确视频 ID 时在管理页提示核对当前视频画面。
- 普通视频观察工具在消息或分享面板打开时会隐藏页面正文并拒绝截图，避免向模型传入聊天画面。页面快照仅供管理员本机核对，可能包含当前会话界面；不送入模型或存入草稿数据库。草稿正文和联系人元数据会保存在本机数据库，最多保留 1,000 条记录。
