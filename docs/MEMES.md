# 表情包管理器

这是适配Limen插件系统的本地表情插件，参考 [AstrBot 表情包管理器](https://github.com/anka-afk/astrbot_plugin_meme_manager)的分类管理、普通分类标签选图和收集审核流程独立实现。无需 AstrBot、图床或额外选图模型。

## 开始使用

1. 更新源码后，完全退出原机器人进程并重新运行 `start.cmd`；网页“重启生效”仅用于配置，不能保证加载新源码。
2. 打开左侧“插件”，进入其中的“表情图库”，点击“安装表情插件”。也可将 `npm run memes:export` 生成的 `dist/meme-manager.plugin.json` 导入插件管理子页。安装后默认停用，不会重复安装第二份。
3. 上传自己的 PNG、JPEG、GIF 或 WebP 图片并选择分类。同内容只保存一份，GIF 保留原始字节；每张最多 5 MiB（若全局媒体限制更低则采用更低值），图库最多 2000 张。
4. 展开“使用规则与自动收集”，填写允许的好友或群聊，再保存并启用插件。范围独立于 AI 白名单，群聊默认需要 @机器人；允许全部会话需要显式勾选。
5. 如需 AI 选图，先在“全部设置”开启 AI 自动回复，配置模型与对应白名单，再开启图库的“AI 回复选图”。仅已入库图片用于回复。

内置开心、难过、生气、疑惑、喜欢、惊讶、疲惫、庆祝及未分类。可以新建/编辑分类与描述；分类描述会提供给 AI。删除分类会将图片移至“未分类”，保留文件。

## 图库与聊天

图库支持分类筛选、名称和标签搜索、24 张分页、原图预览/下载、名称/标签编辑、多选移动、删除及批量审核。每次最多上传 20 张，逐张处理并校验实际图片内容，不接受 SVG 或伪装的非图片。预览通过管理员认证代理，页面不会包含管理员 Token。

| 指令 | 用途 |
| --- | --- |
| `/表情 帮助` | 查看用法 |
| `/表情 分类` | 查看分类及已入库数量 |
| `/表情 发 开心` | 从分类选择一张图片 |
| `/表情 搜 关键词` | 按名称、标签或分类描述找图 |
| `/表情 添加 开心`，同一条消息附图 | 添加到分类，仅“管理好友 QQ 号”允许的发送者可使用 |

也支持 `/表情管理` 前缀。指令处理后不再触发 AI；普通消息继续后续插件及原有 AI 流程。

所有聊天 `/` 指令还要求发送者位于“全部设置 → 回复范围 → 聊天管理员 QQ ID”（`BOT_ADMIN_IDS`）中；留空时禁用。`/表情 添加` 还需满足图库原有的聊天上传权限。网页图库管理不受聊天 QQ 号权限影响。

## AI 选图

插件将有已入库图片的分类及描述提供给当前回复模型。模型可在文字后附加 `[[表情:开心]]` 标签；也兼容中文冒号 `[[表情：开心]]` 和标签内部空格。发送前移除标签，先发送文字，再单独发送一条纯图片消息；图片不带配文、引用或 @，文字仍遵循原回复设置。只索要表情时仅发图，聊天 `/表情 发` 的图片也独立发送。普通聊天没有标签、分类未知、概率未命中或处于冷却时，继续发送正文。

也兼容模型省略前缀后的 `[[开心]]`、`[[摆烂]]` 等简写，分类名或 ID 必须确实存在于本机图库；未知简写、数组和代码示例保留为普通文本。选图预览与实际发送共用解析规则，普通群聊、主动聊天和流式回复均可使用；提示词仍要求模型输出完整格式。未选中图片时，识别出的标签也不会出现在 QQ 正文中。

显式标签还兼容单括号 `[表情:开心]` 和全角格式 `【表情：开心】`、`［表情：开心］`，括号必须成对。单括号需要保留“表情:”前缀，普通 `[开心]` 和 `[表情]` 文字不会被当作选图指令。流式发送会缓冲尚未完整生成的标签头，避免长分类 ID 被提前发出；AI 语音工具与自动转换也会在合成前清除控制标签，保留普通文字和代码示例。

分类标签支持分类名称、内置分类 ID 和自建分类的完整 UUID。Agent 工具返回自建分类 ID 时，选图与预览使用同一个解析流程，不受分类名称 30 字长度限制影响。

明确的“发个表情包”“发一个表情”“请发一个开心的表情包”等请求，在 Agent 提供并允许 `meme_reply` 工具时要求模型调用该工具，分类仅允许当前有已审核图片的分类。只索要表情包时按图片回复处理：不发送模型的额外配文，避免出现图片已发出却声称“只能发文字”的矛盾。该请求的正文在最终选图前不会流式发送到 QQ；普通聊天中的文字配图仍保留正文。

同一用户在刚收到纯表情图片后说“再发一个”“换一张”等，会按继续索要表情处理，仍需实际调用选图工具。识别依赖同一机器人、会话、发送者的上一条已完成图片任务和保留的上下文；其他用户的图片、单纯输出的 `[表情]` 文字以及已通过 `/new` 清空的历史不会作为依据。表情计划随任务保留和清理，常规维护不会提前丢掉识别依据。

已选中表情图片时，图片优先于按概率触发的自动语音，避免语音转换移除分类标签、丢掉图片。仅文字的普通回答继续按原语音配置处理，明确调用语音工具的回复保留原流程。自动语音不会朗读内部的纯 `[表情]` 占位符。AI 选图仍遵循审核、范围、概率与冷却；只索要表情包却未选中图片时，返回未选中或冷却等实际提示，不把它转换成自动语音。

默认选图概率为 1，AI 发图冷却为 30 秒。选择结果持久化，同一任务重新规划、发送重试及进程恢复继续使用同一图片；发送结果未知时沿用原有核对流程，不自动重发。图片已删除或不可用时回退文字；纯图片请求会明确说明图片不可用，任务详情和历史保存实际发送的提示。

文字与图片分开发送时，文字成功后记录独立回执。图片确认未发送的可重试失败只补发图片，不重复文字；任何一条发送结果未知都停止自动重发。流式已发出的正文同样按回执跳过。

“选图预览”按输入描述、分类关键词或显式标签演示本地选择，不调用模型，也不发送 QQ 消息。插件模拟测试不收集图片、不发送消息。

## 自动收集与审核

默认关闭。开启后仅处理允许范围内的图片，每个会话每分钟最多处理第一张；通过驱动已下载的缓存读取，不从聊天任意提供的 URL 发起请求，按内容哈希去重。

默认先人工审核，待审核最多 200 张，审核前不用于回复。可调整分类后入库或删除候选；删除待审核图片会忽略相同内容的后续收集。关闭人工审核后，新收集图片直接入库，已有候选仍需处理。

此版本不使用视觉模型判断是否为表情，也不自动理解图片内容；分类建议只参考消息文字与已有分类关键词。请按范围控制来源并人工整理。

## 数据与边界

- 元数据位于 `DATA_DIR/bot.sqlite`，文件位于 `DATA_DIR/memes/files`；备份保留两者。
- 图库独立于聊天历史保留。停用或删除插件会停止收集与选图，已有图库仍可管理。
- 暂不包含资源广场、外部包安装、云同步、多包/人格绑定、视觉自动分类或向量检索。
- 普通脚本也支持 `{message:[{type:'image',data:{file:'绝对路径、HTTP URL 或 base64://...'}}]}`，最多 5 个文本/图片段，沿用原有发送限流。

## 验证

`npm test` 运行回归；`npm run memes:qa` 使用隐藏 Chrome 验证上传、去重、编辑、审核、规则冲突和桌面/手机布局，报告及截图在 `.impeccable/review/memes/`，全部使用明确标记的模拟图片。未向真实 QQ 联系人发送测试表情。
