# 流动记忆 Living Memory

这是Limen原生的 JavaScript 内置插件，参考 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 的自动整理、召回及生命周期设计独立实现，不依赖 AstrBot、Python 或 FAISS。源码未复制上游实现。

## 安装

更新源码后，先在原启动窗口按 `Ctrl+C` 完全退出，再重新启动项目。进入 **插件 → 流动记忆** 打开独立记忆主页；尚未安装时点击“安装记忆插件”，然后通过“插件配置”设置允许触发的好友或群聊并启用。也可从插件概览进入此页，或在“插件 → 插件管理”的内置插件列表中安装。网页首次安装默认停用。

也可运行：

```powershell
npm run memory:install
```

首次安装沿用当前 AI 好友和群聊白名单，有范围时自动启用，否则保持停用。不会扩大 AI 回复范围。重复运行保留现有配置、范围和启停状态。运行中的服务通过管理员接口安装；离线安装先取得数据目录独占锁。

导出可导入的插件包：

```powershell
npm run memory:export
```

输出 `dist/living-memory.plugin.json`，可在已更新执行层的Limen中导入。普通插件包不能为旧版本宿主补充记忆生命周期入口；导出模板不含你的记忆或已配置的密钥。

## 3D 记忆主页

**插件 → 流动记忆**（`#memory`）按会话、群内用户和人格展示已保存的记忆。每条显示的记忆拥有一个节点和一条神经连接，另有一个不计入记忆数的根节点；新增一条记忆增加一条连接，编辑同一条不会增加连接，删除则移除对应连接。后台保存的新记忆会自动刷新到页面，搜索和状态筛选同时影响图谱与列表数量，空库不填充示例数据。

- 拖动旋转，滚轮或双指缩放；也可使用放大、缩小、复位和暂停按钮。画布获得焦点后，方向键旋转，`+` / `-` 缩放，`Home` 复位。
- 点击节点、连接或列表中的条目查看详情；可新建、编辑名称与正文、修改类型和标签，以及归档、恢复或删除。
- 图中按事实、偏好、关系、计划、事件分支着色；归档连接变暗。分支仅用于浏览，不代表生物神经活动或推断出的语义关系。
- 手机页面按顺序排列图谱、列表和详情。WebGL 不可用时保留列表及全部管理操作；系统开启减少动画时默认暂停流动，离开页面停止渲染。

管理页使用现有 SQLite 记忆库，**不需要 Embedding 模型即可使用 3D 页面、手动保存和关键词召回**。图形在浏览器本地生成，不额外请求模型。自动总结仍使用已配置的对话模型，可选 Embedding 仅改善语义检索。

本机管理台可在插件停用时维护已有记录，并查看历史人格的数据；QQ 运行时仍受插件范围、启停和当前人格隔离约束。新建记忆固定保留；编辑保留原固定状态、归档状态和有效期。编辑、归档和删除会中止当前用户及人格的旧总结，并清空其待总结对话，避免旧内容覆盖修改或重新写回。其他用户不受影响。并发修改或名称冲突会拒绝覆盖，页面保留草稿供核对。

`npm run memory:qa` 使用隔离演示数据和隐藏 Chrome 验证真实 WebGL、增删改连接同步、鼠标及键盘交互、用户隔离、草稿、减少动画、无 WebGL 回退及六种屏幕宽度。截图与报告位于 `.impeccable/review/memory-network/`。

## 工作方式

1. 生成回复前，根据当前用户消息召回相关有效记忆，并在字符预算内作为临时资料追加到本次模型请求。不会把注入内容保存进短期历史。
2. 仅在 QQ 回复确认发送成功后记录一轮对话。默认累计 **8 轮**后后台调用当前 AI 模型整理长期事实，不阻塞回复发送。可用 `summary_model` 指定同一模型服务上的独立模型。
3. 总结产生稳定名称、正文、类型、重要性、关键词和有效期；同名事实更新，完全相同的名称不重复建立记录。总结失败保留待整理原文，可通过指令重试；批次中的写入和游标推进在一个 SQLite 事务中提交。
4. 本地中文双字词元 BM25 与可选向量检索通过 RRF 融合排序。命中会强化重要性；未固定的记忆按时间指数衰减，低于阈值或过期后归档。归档记录可查看、恢复或删除，不再自动注入。手动保存的记忆固定保留，自动总结不会覆盖它。

自动总结使用额外的模型请求，费用随模型服务计费。关闭 `auto_summarize` 后仍可手动保存、召回及执行 `/lmem summarize`。每个用户及人格最多保存 500 条（包括归档），达到上限时保留原文并报告总结失败，需要先删除旧记忆。待总结原文最多 80 轮，超出时淘汰最早轮次。

## 隔离与保留

记忆按 **机器人账号 → 会话 → 群内发言人 → 人格** 隔离。管理员指令也只作用于管理员本人在当前会话和人格的记忆。群里只捕获当前发言人的原始消息，不采集共享背景、其他成员消息或混合回复中的事实；因此 Chat Plus 合并的其他成员消息不会自动写进当前用户记忆。

插件会话范围、群聊 @ 要求及固定群成员屏蔽继续生效。需要与 Chat Plus 的无 @ 回复配合时，可关闭记忆插件自身的“群聊需要 @”。网页试聊和主动话题不读写此插件的记忆；原有 `memory_search/save/forget` 手动记忆系统继续独立工作。

`/new` 清空短期上下文及待总结对话，保留已保存的长期记忆。切换人格会清空待总结对话；插件更新、停用、删除、忘记或重置会阻止旧后台总结提交。删除插件会同时删除其长期记忆及原文。停用插件保留已有数据。

数据保存在 `DATA_DIR/bot.sqlite` 的 `living_memories`、`living_memory_turns` 和 `living_memory_captures` 表中，与数据库一起备份。长期事实不受普通任务历史保留天数影响。原文默认保留 30 天；总结来源仅用于追溯，不参与检索、提示词注入或 Embedding。常见凭据格式会拒绝写入；请勿将凭据作为需要长期记住的内容。

## 指令

所有 `/lmem` 指令沿用 `BOT_ADMIN_IDS` 管理员权限，且需要匹配插件范围。

| 指令 | 用途 |
| --- | --- |
| `/lmem help` | 查看帮助 |
| `/lmem status` | 当前用户及人格的有效/归档数量、待总结轮数、总结状态 |
| `/lmem remember 名称 \| 内容` | 保存或更新固定记忆 |
| `/lmem search 关键词` | 检索并强化相关记忆，最多按召回条数返回 |
| `/lmem list` | 最近 12 条记忆的 ID、名称及状态，含归档 |
| `/lmem summarize` | 后台整理当前未总结原文，少于阈值也可触发 |
| `/lmem forget ID` | 删除一条记忆，同时清空当前用户及人格的待总结原文，防止旧总结立即写回 |
| `/lmem archive ID` | 归档一条记忆，同时清空待总结原文 |
| `/lmem restore ID` | 恢复记忆，取消其有效期，恢复重要性 |
| `/lmem reset` | 清空当前用户及人格待总结原文，保留已整理的长期记忆 |

插件管理中的模拟测试仅识别指令，不读写真实记忆，也不请求模型。

## Agent 工具

启用 Agent 后，匹配范围内自动提供：

- `recall_long_term_memory(query)`：检索当前用户及人格的记忆。
- `memorize_long_term_memory(key, content)`：本轮用户明确要求记住时保存固定记忆。
- `forget_long_term_memory(id)`：本轮用户明确要求忘记时删除记忆，先召回获得 ID。

工具继续受人格工具白名单、任务写入防重及执行时权限复查约束。自然语言保存/删除无需聊天管理员身份，但仅能操作本人记忆。无 Agent 时自动召回、总结和管理员指令仍可使用。

否定表达及提问不会授权记忆工具写入。明确的忘记请求和“不要记录”类消息也不会再次进入自动总结。

## 配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `auto_summarize` / `summary_turns` | `true` / `8` | 自动整理及轮次阈值，2–40 轮 |
| `summary_model` / `summary_timeout_ms` | 留空 / `30000` | 使用现有 AI 地址和 Key；独立模型及 1–120 秒时限 |
| `recall_enabled` / `recall_top_k` / `context_chars` | `true` / `5` / `3000` | 自动召回、条数及本次注入预算 |
| `max_memories` | `500` | 每个用户及人格的总条数上限，10–2000 |
| `decay_rate` / `archive_threshold` | `0.01` / `0.08` | 每日衰减率及归档阈值，按访问时惰性维护 |
| `default_ttl_days` | `180` | 未指定有效期的默认天数；0 为不限期 |
| `source_days` | `30` | 原文保留天数；长期记忆正文继续保留 |
| `embedding_base_url` / `embedding_model` | 留空 | 同时填写启用语义检索，如本地服务的 `/v1` 基础地址及实际模型标识 |
| `embedding_api_key` / `embedding_timeout_ms` | 留空 / `2500` | 独立凭据及单次超时；不会把主 AI Key 发给不同服务 |

Embedding 失败、维度不匹配或更换模型时自动保留关键词召回。向量与模型、基础地址指纹绑定；更换服务后既有记忆仍可关键词召回，后续同名更新时生成新向量。当前不提供批量重建向量索引或语义知识图谱，也不直接读取 AstrBot 数据库。配置中的 Embedding Key 会随插件完整配置导出，分享前清除。
