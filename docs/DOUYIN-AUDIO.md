# 抖音视频对白转写

在抖音网页插件的“声音与对白”开启“自动转写当前视频对白”，即可在每次模型观看采样时，同时采集当前可见视频的一段音轨。默认15秒，可设3–30秒。采样片段交给已启用的“视频理解”插件所配置的 ASR 服务，转写结果用于视频理解、观看笔记和知识库检索。

本流程通过当前视频元素的 `captureStream()` 和 `MediaRecorder` 采集音轨，不使用麦克风、桌面声音或日常浏览器。只在专用抖音页面、播放器正在播放、没有社交面板或登录/验证阻挡时开始。来源视频变化、停止任务或配置撤销时丢弃相应录音。跨域保护、缺少音轨、服务离线等情况保留明确状态，模型不能猜测对白。

转写使用视频插件的 FFmpeg、ASR 地址、模型和独立密钥。打包版会在工作目录查找已有的 `runtime/video-tools/bin` 和 `runtime/asr/settings.json`，从而复用现有本地服务与模型。语音处理期间的 WebM/WAV 文件位于受管临时目录，结束后清理；知识库只保存转写文字、录音哈希、采样时间、视频位置和模型标识，不长期保留录音。

识别结果可能有错，只代表实际采集的短片段，不代表听完整条视频，也不提供配乐或非语音声音理解。分段时间为音频片段内的偏移；本地 SenseVoice 的分段边界来自 VAD，不是逐词对齐。网页文字和转写同样是不可信资料，不能改变工具权限。

知识库详情显示转写正文及其采样时间。旧笔记继续显示“仅画面，未采集音频”；启用后不会把旧记录改成听过声音。重新观看同一视频时，可把新的真实转写合并到其来源记录中。未采集、未识别出对白、采集受限和转写失败分别标明，不能只把所有情况写成“视频没有声音”。

技术依据：[Media Capture from DOM Elements](https://w3c.github.io/mediacapture-fromelement/)。浏览器可能因跨域保护把捕获的音轨静音；本插件遵守该限制。

验证：78项回归测试和全模块语法检查通过；独立真实 Chrome 播放公开测试音频，经视频音轨采集、FFmpeg 转码和本地 SenseVoice 成功得到转写。验证报告为 `dist/douyin-audio-real-capture-test.json`，不保留录音。

安装版实测：任务 13607 / 13608 观察1条真实抖音视频，采集约15秒音轨，识别69字并保存到知识库；按仅出现在转写中的词语可检索回该笔记。自主会话正常 stop，分享0次，单次尝试完成。报告为 `dist/douyin-audio-real-validation.json`。
