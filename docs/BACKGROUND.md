# 背景壁纸

工作台的“背景壁纸”用一张本机图片替换默认的灰白底色：侧栏、顶栏和内容面板改为半透明白色，图片透过面板显示。它由内置插件 `background` 提供，不处理聊天消息，也不需要 QQ 会话范围。

## 开始使用

1. 更新源码后完全退出原服务并重新运行 `start.cmd`（或重新打开桌面版）；网页“重启生效”只重载配置，不会加载新的页面模板。
2. 打开左侧“插件”，进入“背景壁纸”，点击“安装背景插件”。安装后默认停用。
3. 点击“启用插件”。该插件不处理消息，因此无需填写好友或群聊范围。
4. 点击“选择图片”，挑选 PNG、JPEG 或 WebP，单张不超过 8 MiB。上传后立即生效，图片同时出现在“效果预览”中。
5. 如需微调，拖动“模糊”“白色遮罩”“面板不透明度”后点击“保存设置”。滑块只改变预览，保存后才写入配置并作用于整个工作台。

停用插件或关闭配置里的“应用背景”会恢复默认外观，图片仍保留在本机；点击“移除背景”才会删除图片文件。

## 显示参数

| 参数 | 配置键 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 应用背景 | `enabled` | 开 / 关 | 开 | 插件启用时的总开关 |
| 图片适应方式 | `mode` | `cover` / `contain` / `tile` | `cover` | 填满窗口（可能裁切）、完整显示、平铺重复 |
| 模糊 | `blur` | 0–24 | 0 | 像素；数值越大越安静，也越耗显卡 |
| 白色遮罩 | `veil` | 0–0.9 | 0.34 | 覆盖整页的白色蒙层，保证深色图片上的文字可读 |
| 面板不透明度 | `panel` | 0.4–1 | 0.9 | 面板、侧栏、顶栏与保存栏的白底透明度 |

工作台只有浅色主题，因此遮罩是白色而不是黑色。深色或高对比图片建议把遮罩提高到 0.45 以上；图片本身较淡时可以降到 0.2 左右。

## 存储与边界

- 图片保存在数据目录的 `background/` 下：`wallpaper.<png|jpg|webp>` 与记录尺寸、格式和 SHA-256 的 `state.json`。
- 每次上传都会替换旧文件，`clear()` 与删除插件都会连同记录一起清理，不会堆积多份图片。
- 读取图片时重新校验 SHA-256，文件被替换或损坏会返回 409 并提示重新上传。
- 只接受 PNG、JPEG、WebP；GIF 等动图会被拒绝，避免整页动画。
- 页面通过同源代理读取图片，CSP 保持 `img-src 'self' data:`；页面本身不含管理员 Token。
- 删除插件记录会清空背景目录，重新安装后从默认外观开始。

## 接口

与其他内置插件一致，接口只接受管理员 Token：

| 接口 | 参数 / 结果 |
| --- | --- |
| `GET /admin/background` | 返回插件记录、图片元数据与当前显示参数 |
| `POST /admin/background/action` | `{action:"upload",data:"data:image/png;base64,…"}`、`{action:"remove"}`、`{action:"save",mode,blur,veil,panel,enabled}` |
| `GET /admin/background/image` | 返回图片字节，附带 `Content-Type` 与 `Content-Length` |
| `GET /admin/status` | `appearance` 字段供工作台首屏直接套用当前外观 |

工作台侧边代理为 `/background`、`/background/action`、`/background/image`；写入同样要求同源 `Origin`。首屏通过 `/state` 的 `appearance` 一次拿到参数，轮询期间按签名比对，不会重复改动 DOM。

## 换机器与分发

插件包只依赖自己的目录与 `plugins/_host`，不含绝对路径、不 import `src/`、不需要第三方 npm 包；图片路径在运行时取自数据目录。换机器有两条路：

1. **复制目录**（推荐）：把 `plugins/background/` 整个目录放进目标机器的 `plugins/`，重启服务，再到“插件 → 背景壁纸”点“安装背景插件”并启用。
2. **打包 zip**：在“插件管理 → 插件包”填路径安装。zip 内路径必须是正斜杠：Windows 的 `Compress-Archive`（以及部分版本资源管理器的“压缩为 ZIP”）会写成 `background\config.mjs`，宿主会以“插件包包含无效路径”拒绝，这是防路径穿越的检查。用 7-Zip 或 `tar -a -c -f background.zip background` 生成的包可以正常安装。

需要一起带走的东西：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 插件代码 | `plugins/background/` | 5 个文件、约 12 KiB |
| 宿主支持 | `src/onebot.mjs`、`src/web/{background,page,client,plugin-hub,login-server}.mjs` | 接口与界面由宿主提供，旧构建没有这些文件 |
| 已保存的图片 | `DATA_DIR/background/` | 不随插件包走；只有迁移数据目录时才会带过去 |
| 插件记录与参数 | `DATA_DIR/bot.sqlite` | 换机器需要重新安装并启用；参数不迁移则使用默认值 |

结论：**同一版本的应用可以直接搬**；目标机器若是更早的构建，插件包能被扫描甚至保存，但没有“背景壁纸”页面和 `/admin/background` 接口（请求会返回“管理员接口不存在，请检查服务版本…”），必须把宿主一起升级。只有插件、没有宿主改动时，控制台其余功能不受影响——客户端会跳过缺失面板的事件绑定。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 打开“背景壁纸”提示插件包未安装 | `plugins/background` 未随包分发或被删除，重新放回目录后重启服务 |
| 上传提示图片无效 | 确认是 PNG/JPEG/WebP 且小于 8 MiB；改扩展名或 SVG 会被拒绝 |
| 图片已上传但页面没变化 | 检查插件是否启用、配置里“应用背景”是否打开；两者都满足后刷新页面 |
| 文字看不清 | 提高“白色遮罩”，或提高“面板不透明度”，也可降低模糊 |
