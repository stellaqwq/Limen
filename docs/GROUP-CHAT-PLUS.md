# 群聊增强 Chat Plus

参考 [Him666233/astrbot_plugin_group_chat_plus](https://github.com/Him666233/astrbot_plugin_group_chat_plus) 的功能设计，为Limen独立实现的 JavaScript 内置插件。参考仓库使用 AstrBot Python 接口；本插件接入本项目自己的消息插件、Agent、群聊上下文和持久化任务队列，不安装或运行 AstrBot。

## 功能

| 能力 | 本项目实现 |
| --- | --- |
| AI 读空气 | 普通群消息先经过概率、时段、冷却和密度筛选，再由独立无工具模型判断是否适合参与；失败或无效判断保持沉默 |
| 动态回复倾向 | 按用户追踪 0–1 注意力，指数衰减；兴趣词提高概率，近期回复密度降低概率；关闭注意力时可使用回复后临时概率提升 |
| 多人群上下文 | 复用群聊背景，标明发言人、时间、@ 和引用；未回复的消息仍可供后续参考 |
| Smart 消息合并 | 合并短窗口内的连续消息，一批生成一条回复；保留最早消息为主回复对象，其他人的补充作为有来源的背景 |
| 空 @ 等待 | 只 @ 机器人时可等待后续消息，不伪造 @ 或修改真实发送人 |
| 优先与过滤 | @机器人、触发关键词和回复机器人可直接进入回复；支持用户 / 关键词黑名单及避免插入 @他人的聊天 |
| 情绪系统 | 对开心、难过、生气、疑惑识别轻量关键词线索，检测简单否定并随时间衰减，影响措辞；不是心理状态诊断 |
| 定时主动聊天 | 在配置群内，根据先前活跃度、沉默时长、概率、静默时段、未回应次数及每日上限调度自然话题 |
| 图片描述缓存 | 使用多模态模型描述图片，按插件、群、模型及图片内容摘要缓存；未 @ 图片可在后台处理，后续询问能参考描述 |
| 防重复与内容过滤 | 完整生成后检查近期相同回复及禁止输出词，再交给文字 / 表情 / 语音流程 |
| 管理与恢复 | 管理员状态 / 暂停 / 恢复 / 概率 / 重置 / 清图片缓存；判断结果与任务持久化，生成重试不重新抽概率或重复判定 |

仍使用本项目的人格、显式记忆和工具权限。自动主动话题只提供只读工具，不执行记忆写入、发说说等写入工具。普通回复引用并 @ 实际主提问者；主动话题没有新的发送人，不引用或 @ 旧用户。

## 安装

```powershell
# 按指定群安装启用，并将这些群加入原有 AI 群白名单
npm run groupchat:install -- --groups 1036914541

# 导出给同版本项目使用
npm run groupchat:export
```

安装脚本保留原有群白名单、插件高级配置和其他插件，开启群聊上下文；在线时通过管理员接口保存，离线时使用项目运行锁。首次更新代码后应退出旧机器人进程并重新运行 `start.cmd`，以加载新增执行层。`dist/group-chat-plus.plugin.json` 是内置插件配置包，需要本次更新后的后端；不能直接导入 AstrBot。

启动后进入侧栏“插件”，在概览或页内导航中打开“群聊增强”。也可在“插件 → 插件管理 → 群聊增强 Chat Plus → 管理面板”打开专用页面。当前提供 60 项中文配置，按参与概率、读空气、注意力与情绪、触发过滤、主动聊天、安静时段、图片描述、回复输出分组，可搜索并即时保存。原有 JSON 编辑与导入导出仍可使用。

插件范围必须包含目标群，同时该群必须在 AI 群白名单中。范围中的“群聊需 @”若打开，会恢复仅 @ 参与并禁用主动聊天；默认关闭，采用本插件自己的参与判断。私聊仍由原有流程处理。

“全部设置 → 回复范围”的固定群成员屏蔽规则优先于插件参与概率、@触发和管理员指令；被屏蔽成员的消息不更新注意力、情绪、活动时间或近期背景，也不触发后台图片描述。规则支持指定群及所有群，配置与保留边界见 [固定屏蔽群成员](WEB.md#固定屏蔽群成员)。

## 专用管理页

- **状态与会话**：每 10 秒读取当前群的参与开关、概率、最近筛选原因、主动聊天次数及无人回应次数。
- **全局配置**：设置允许群、默认参数和各阶段行为；保存后即时用于后续任务。
- **群专属配置**：为每个群勾选需要单独覆盖的参数，未勾选的值随全局默认更新；支持暂停 / 恢复、临时概率、成员注意力与情绪线索查看及重置对话。
- **图片与上下文**：按群查看图片描述、模型、时间及近期上下文；可删除单条图片描述或清空当前群缓存。

“运行监控 → 任务队列 → 查看消息与回复”还会展示 AI 读空气的结论、简短判断理由、置信度及参与门槛。例如判断不适合参与时，可看到“成员正在相互交流，机器人暂时没有需要补充的信息”。模型选择参与但置信度不足时，会单独说明门槛拦截；请求失败、输出格式错误或模型没有给理由时显示相应提示，不编造理由。

只保存模型最终返回的简短 `reason`，最多 300 字，不保存思维链、原始判断响应或服务异常内容，也不将理由写入运行日志。理由作为任务诊断独立保存，随任务的历史保留期限清理；忽略任务的原消息和回复正文仍按原有设置脱敏。重启后仍可查看已保存理由。旧版本任务没有保存过理由，页面会明确提示无法补回；未通过概率、冷却等前置筛选而未调用读空气模型的消息没有 AI 判断理由。

全局、每群覆盖、临时概率的优先级依次提高。清空临时概率可恢复配置。群专属设置单独持久保存，`/new` 和重置对话不会删掉它们；重置会清除共同的短期上下文、注意力、情绪与临时概率，人格和显式记忆保留。有未完成或待核对任务时拒绝重置。页面保留未保存的草稿，过期修订号返回冲突，不静默覆盖其他窗口的修改。

配置与管理架构的源码拆解及未移植差异见 [CHAT-PLUS-ASTRBOT-STUDY.md](CHAT-PLUS-ASTRBOT-STUDY.md)。

## 管理员指令

以下指令只允许 `BOT_ADMIN_IDS` 中的账号，在插件已配置的群使用。`/tools` 也会列出入口。

| 指令 | 作用 |
| --- | --- |
| `/gcp_help` | 完整指令说明 |
| `/gcp_status` | 当前群开关、概率、最近判断、情绪线索、主动聊天计数及图片缓存数量 |
| `/gcp_pause` / `/gcp_resume` | 暂停 / 恢复当前群的增强回复和主动聊天 |
| `/gcp_probability 0.06` | 设置当前群运行时概率，0–1；仍检查冷却与读空气 |
| `/gcp_reset_here` | 清空当前群短期上下文、注意力、情绪、概率和冷却，保留人格与显式记忆 |
| `/gcp_reset` | 对所有已记录的插件群执行上述重置；任何群有未完成或待核对任务时不执行 |
| `/gcp_clear_image_cache` | 只清空当前群的图片文字描述缓存 |
| `/new` | 与当前会话新对话指令衔接，同时清空群背景和运行状态 |

## 常用配置

所有配置默认值均随导出的 JSON 给出，后端会检查类型、范围及未知字段。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `initial_probability` | 0.06 | 普通消息参与筛选的基础概率 |
| `decision_ai_enabled` | true | 概率命中后是否继续由 AI 读空气 |
| `decision_model` | 空 | 判断模型标识；空使用当前模型，共用现有服务地址和 Key |
| `decision_timeout_ms` | 12000 | 判断请求超时；判断不使用工具、人格写入或私密推理日志 |
| `decision_reasoning_effort` / `decision_max_output_tokens` | none / 512 | 判断模型的独立推理强度与输出 Token 上限；none 明确关闭思考，留空不传推理参数 |
| `decision_extra_prompt` | 空 | 追加判断规则 |
| `attention_enabled` | true | 启用按成员衰减的注意力 |
| `attention_half_life_seconds` / `attention_gain` / `attention_boost` | 120 / 0.18 / 0.55 | 衰减半衰期、互动增加量及对概率的影响 |
| `after_reply_probability` / `boost_duration_seconds` | 0.6 / 90 | 关闭注意力时，回复后的短期概率提升 |
| `cooldown_seconds` / `max_replies_per_minute` | 12 / 3 | 普通消息参与冷却及每分钟密度限制，直接 @ 可继续问答 |
| `trigger_keywords` / `interest_keywords` | [] / [] | 优先触发词 / 提高参与倾向的兴趣词 |
| `blacklist_users` / `blacklist_keywords` | [] / [] | 不参与回复的用户或关键词，相关背景也从插件请求中排除 |
| `ignore_mentions_others` | true | 没有 @机器人时，避免插入 @他人的对话 |
| `merge_window_ms` / `max_batch_messages` | 1200 / 8 | 连续消息合并窗口及最大批次条数 |
| `empty_at_wait_ms` | 4000 | 空 @ 的等待窗口 |
| `quiet_hours_enabled` / `quiet_start` / `quiet_end` / `timezone` | true / 23:00 / 07:00 / Asia/Shanghai | 普通参与与主动聊天的静默时段，支持跨午夜；直接呼叫仍可回复 |
| `mood_enabled` / `mood_decay_seconds` | true / 300 | 情绪措辞提示及过期时间 |
| `reply_style` | 空 | 追加回复表达规则，原有人格继续有效 |
| `duplicate_filter` / `output_block_words` | true / [] | 近期完全相同内容过滤 / 禁止输出词列表 |
| `typing_delay_ms` | 0 | 完整回复就绪后的可选等待时间 |
| `interest_boost` / `density_penalty` / `low_information_multiplier` | 0.2 / 0.5 / 0.35 | 兴趣词增量、近期回复密度惩罚、低信息消息倍率 |
| `decision_confidence_threshold` | 0.5 | AI 读空气判断的最低置信度 |
| `neutral_style` / `happy_style` / `sad_style` / `angry_style` / `confused_style` | 各情绪默认措辞 | 可编辑的情绪表达建议 |
| `duplicate_window_seconds` | 1800 | 重复内容检查的时间窗口 |
| `image_caption_reasoning_effort` / `image_caption_max_output_tokens` | none / 2048 | 图片描述的独立推理强度与输出 Token 上限 |
| `proactive_unanswered_limit` | 5 | 连续无人回应达到上限后等待成员再次发言；黑名单成员不解除限制 |

开启完整回复的重复 / 禁止词检查时，QQ 需要等检查通过后发送，模型请求仍以流式读取；关闭 `duplicate_filter` 且不设置 `output_block_words` 时，普通增强回复可沿用边生成边分段发送。此检查在自动语音转换之前完成，避免过滤后仍发送语音。

## 主动聊天

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `proactive_enabled` | true | 定时主动话题开关 |
| `proactive_silence_seconds` | 600 | 群中用户与机器人均安静达到此时长后才考虑 |
| `proactive_probability` / `proactive_check_seconds` | 0.3 / 30 | 检查概率与间隔 |
| `proactive_min_user_messages` / `proactive_activity_window_seconds` | 4 / 1800 | 先前活跃度要求，避免在没有聊天的群无故发言 |
| `proactive_cooldown_seconds` | 900 | 两次主动调度的基础间隔；无人回应时逐步延长 |
| `proactive_max_per_day` | 3 | 每群每日最多调度次数，按配置时区统计；失败也计入，防止重试刷屏 |

QQ群离线、插件或当前群暂停、有排队 / 生成 / 发送 / 待核对任务、静默时段、活跃度不足或达到上限时均不调度。不重放离线期间的定时任务；每次调度先持久化唯一任务，再交给现有执行与发送确认流程。

## 图片描述

`image_caption_enabled=true`、`caption_unmentioned_images=true` 默认开启。当前模型需要视觉能力，或在 `image_caption_model` 指定同一模型服务上的视觉模型。描述请求默认超时 `image_caption_timeout_ms=20000`，每群缓存默认最多 `image_cache_max_entries=500` 条，保留 `image_cache_days=7` 天；每群覆盖独立应用，清理一个群不会按该群的天数清掉其他群的缓存。

后台图片描述最多并行两条；繁忙时跳过额外背景任务，直接提问图片仍会走原有附件分析。成功描述后，缓存只有内容摘要和文字，不保存 Base64；相同图片会复用描述，不同群和模型隔离。描述失败时保留原图供原有多模态流程处理。后台描述完成后才可供后续提问参考，不承诺从未下载成功的图片中读取内容。

读空气与图片描述默认使用 `reasoning_effort=none`，明确关闭辅助思考；正式回复仍使用“AI 与回复”中配置的推理强度。服务不支持 `none` 时可将对应推理强度留空；若使用必须思考的模型，应增加辅助 Token 上限。输出 Token 上限包含思考和最终正文，512 个思考 Token 不等于已经生成判断 JSON。

模型异常时，任务详情会展示请求耗时、超时设置、停止原因、服务状态码及服务返回的输入 / 输出 / 思考 Token 统计，区分超时、只有思考、空回复和响应中断。流式辅助请求请求用量统计；服务未提供的数字不伪造。图片描述失败会产生独立的“群图片描述失败”诊断日志。排查示例见 [本地模型诊断](LOCAL-MODEL-DIAGNOSTICS.md)。

## 状态与兼容边界

运行状态、自动回复授权、判断结果和图片描述分别存入 `group_chat_state`、`group_chat_jobs`、`group_chat_images`。与现有群背景缓存一样，状态会保存群消息的有限摘录，独立于忽略任务正文开关；原有保留维护会清理状态，图片按独立期限清理。插件配置改动或停用会撤销旧任务授权并取消相关等待；未知发送结果仍需人工核对，不自动重发。

本次实现覆盖群聊参与和所选进阶功能，并复用本项目的记忆、附件、语音、表情与网页管理。专用管理页已集成在本机工作台。原仓库的 AstrBot / LivingMemory 专用接入、任意媒体转写、戳一戳 / 反戳和合并转发读取没有直接移植：其中部分缺少当前 QQ 内核驱动动作支持。错别字生成、动态时段概率和无回应“吐槽”等机制尚未实现。源码功能对照基于 2026-10-28 阅读的上游 README、配置定义与模块接口。
