# 流式输出与引用回复

默认开启 `AI_STREAM_ENABLED=true`。兼容 Chat Completions 的模型请求使用 `stream:true`；支持标准 SSE、跨网络块的 UTF-8、工具调用参数片段、结束标记和安全用量诊断。服务返回普通 JSON 时仍可回复；只支持非流式请求的服务可关闭此配置。

QQ 按完整句子或 `AI_STREAM_CHUNK_CHARS` 分段发送，默认目标为 240 个字符，范围 40–1000。单条回复总长度仍受 `AI_MAX_REPLY_CHARS` 限制，各段遵守原有全局和同会话发送间隔。同一会话的后续任务等当前回复结束后执行。

文字与图文回复引用触发消息的 OneBot `message_id`；群聊同时 @ 该消息的发送人，私聊不加 @。消息插件及聊天指令也采用此规则。手工调用 OneBot 发送接口时按调用者提供的消息段发送，不自动增加引用或 @。语音保持独立 `record` 消息；明确语音请求或非零概率语音转换先收齐完整内容，再调用既有语音流程。

每个提前发送的 QQ 段先写入 SQLite `reply_stream_parts`，再等待现有驱动的明确发送确认。完整生成后只发送尚未发送的正文尾部及已规划的图片。中断后的已发送部分不会自动重发；状态未知的段进入任务核对，详情列出各段状态和消息 ID。尚未提交任何段的模型失败仍按原有生成次数上限重试。不会将部分回复写入完整会话历史。

默认官方内核驱动支持 `at` 和 `reply` 消息段。引用 ID 按账号解析，且必须属于发送目标所在的同一会话；找不到来源时明确失败。旧缓存缺少引用序号时，宿主按原消息 ID 查询。实验 native 驱动的引用发送仍不支持。

网页测试对话通过管理员认证的 `/admin/agent/chat/stream?session=...` 获取本会话状态，工作台代理不向浏览器暴露管理员凭据。浏览器自动重连，后端在连接关闭时释放监听器，普通聊天查询继续可用。

QQNT 字段核对参考：[消息元素及转换定义](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/api/msg.ts)。项目继续使用自己的官方内核宿主，不新增机器人框架依赖。

模拟验证覆盖中文与 emoji 跨字节分块、工具参数拼接、只含推理的响应、流中断与取消、部分发送后的恢复、表情标记、群聊 / 私聊行为、引用来源会话校验、SSE 权限与连接清理。QQ 中的引用展示及 @ 提醒仍需真实账号验收。
