# 本地 VoiceStudio 插件

让项目内置聊天模型通过函数工具调用本机 VoiceStudio，再将返回的 WAV 作为独立 QQ 语音发送。不依赖 AstrBot，也不在机器人进程中加载语音模型。

## 启用

1. 在 VoiceStudio 中下载、启用并成功加载本地语音引擎，先在其界面完成一次生成。默认 API 地址为 `http://127.0.0.1:3900`。
2. 完全退出旧机器人并重新运行 `start.cmd`，加载新增源码。
3. 在“插件管理”导入 `dist/voicestudio.plugin.json`，或通过管理员接口 `POST /admin/plugins/install` 提交 `{"kind":"voicestudio"}`。重复安装返回已有插件，不覆盖配置；新安装默认停用。
4. 编辑插件，填写允许的好友/群聊及 JSON 配置，保存后启用。范围独立于内置 AI 白名单，群聊默认还需要 @机器人。
5. 在“全部设置”配置支持 Chat Completions `tools` 的模型，开启 AI 回复并配置相应白名单。对模型说“用语音说：晚上好”，即可由模型决定调用语音工具。

## 工具和指令

在“插件管理”编辑“本地 VoiceStudio”，会自动读取当前配置服务的已保存音色。到“默认音色 → 已保存音色”选择声音，点击“保存插件”立即生效。列表展示名称和 voice_id，不混入 OpenAI 别名；也可使用“引擎默认音色”。读取失败或音色已删除时保留当前配置，可刷新重试。

音色选择与 JSON 配置的 `voice` 字段双向同步。手动修改服务地址或 API Key 后，点击“刷新音色”按草稿配置读取，无需先保存；此操作不合成或发送语音。切换服务、编辑器或关闭编辑器会取消旧的音色读取，迟到的响应不会覆盖当前草稿。

“语音输出概率（%）”决定普通 AI 文字回复生成后是否转换为语音：0% 关闭自动转换，100% 每次尝试，35% 表示每条符合条件的回复有 35% 概率。使用所选默认音色，保存插件后立即用于后续回复；与 JSON 的 `reply_probability`（0–1）双向同步。旧配置缺失该字段时默认 0，不改变原有行为。

这一步由回复发送流程执行，不要求模型主动调用工具，`ai_tools:false` 时也可按概率转换。仍需启用插件、匹配允许会话，并启用原有 AI 回复及白名单。显式语音工具和 `/vs_say` 不受概率限制；网页测试对话和已经被消息插件处理的回复不参与自动转换。

已选中表情图片时跳过自动转换，按原有流程发送文字和图片。其余普通回答按概率转换，只朗读正文，命中后发送一条独立 QQ 语音。AI 工具和自动转换均在合成前清除表情控制标签，兼容单/双括号、全角括号及图库中已知分类的双括号简写；普通数组和代码示例保留。明确要求仅文字、正文为空、超过 `max_text_chars` 或转换失败时保留原文字，过长回复不截断。每条回复的判定与原始正文持久化，生成中断后回退文字；重试或重启不重新抽签，也不重复请求合成。

- `voicestudio_list_voices({keyword})`：查询已保存音色 ID 和引擎可用性。需要特定声音时先查询。
- `voicestudio_speak({text,voice,speed,instruct,language})`：合成并将本次回复改为语音。只有正文必填；其余留空/语速 0 时使用配置。合成成功后结束本轮模型调用，不再额外生成文字回复或重复合成。
- `/vs_say 正文`、`/本地语音 正文`：不依赖模型，直接朗读。
- `/vs_voices [关键词]`、`/本地音色 [关键词]`：查询音色。
- `/vs_status`、`/本地语音状态`：检查接口并显示可用引擎；接口可访问不等于模型已成功加载。
- `/tools`、`/工具`：查看当前会话可用指令说明。

上述聊天 `/` 指令仅允许“全部设置 → 回复范围 → 聊天管理员 QQ ID”（`BOT_ADMIN_IDS`）中的发送者使用；插件会话范围仍需匹配。留空时所有聊天 `/` 指令都禁用。

原有插件模拟测试不会实际合成或发送语音。独立语音不与文字/图片混在同一消息链。VoiceStudio 不可用时返回明确的文字错误，不声称已经发送语音。

若 `/vs_say` 被模型当普通聊天回答，先检查插件是否启用、允许的好友 QQ 号是否完整且与当前发送者一致。范围不匹配时，直接指令和模型工具都会不可见。启用后的允许会话会自动附加当前语音能力说明，避免旧聊天中“没有语音功能”的回答影响后续工具调用。工具名称属于模型调用接口；聊天中查询音色使用 `/vs_voices`。

明确的“用语音说：晚上好”“请用语音回复”“帮我朗读……”会要求模型调用 `voicestudio_speak`，正文与音色等参数由模型生成。“能调用语音吗”“有哪些工具”及直接提到函数名不再触发原生工具说明或音色查询，按普通聊天处理；需要说明时管理员发送 `/tools`，查询音色使用 `/vs_voices`。普通聊天继续使用自动工具选择；否定请求、引用和讨论语音技术不会触发强制规则。只根据当前消息判断，保留原聊天历史与角色设定。

为兼容本地 Qwen 接口，首轮使用字符串 `tool_choice:"required"` 并仅提供目标工具定义；工具参数仍由模型生成。后续轮次恢复自动选择。系统消息始终位于对话开头，兼容不允许中途追加 system 消息的模板。若模型忽略 required、不返回工具调用，任务会明确记录 `ai_tool_not_called`，不会将“没有功能”当成功结果发送。

## JSON 配置

```json
{
  "base_url": "http://127.0.0.1:3900",
  "api_key": "",
  "model": "tts-1",
  "voice": "default",
  "language": "",
  "speed": 1,
  "timeout_seconds": 180,
  "max_text_chars": 1000,
  "ai_tools": true,
  "reply_probability": 0
}
```

`tts-1` 是 VoiceStudio 当前引擎的兼容别名，也可填写已安装引擎 ID，例如 `omnivoice`。`voice` 使用设置中选中的已保存音色 ID。手动朗读，以及模型未传音色、传空值或 `default` 时，均使用插件配置的默认音色；模型明确指定其他 voice_id 时才覆盖。实际是否本地执行、语言/语气支持、模型许可及权重下载由 VoiceStudio 负责。插件不创建克隆音色或替换模型。

语速允许 .25–4，超时 1–600 秒，正文上限 1–2000 字。固定请求 WAV；按实际容器校验 PCM/float WAV，再沿现有 QQ SILK 编码链发送。单份音频最多采用 `MEDIA_MAX_BYTES` 与 10 MiB 中较小值。

服务地址与 API Key 只由管理员配置，模型不能传入地址、密钥或文件路径。请求不跟随重定向，错误不回显服务响应正文，日志不保存正文或音频。配置以现有插件明文 JSON 方式保存，导出插件会包含自行填写的 API Key，请按现有导出提示处理。

## 任务与缓存

生成在本机串行执行，超时包含等待队列。模型 HTTP 请求与语音合成各自有超时，避免较慢 TTS 被模型请求超时误取消。

AI 工具调用先记录生成状态，成功后将 WAV 保存在 `DATA_DIR/voicestudio`，任务中保存音频引用。发送重试和进程恢复复用同一音频；生成中断或结果未知时不自动再次合成。QQ 投递未知沿用原有“需要核对”流程，不自动重发。停用插件后，准备发送的语音回退为任务文字。

缓存上限 200 MiB；每小时清理无活动任务引用且超过 24 小时的音频，保留待发送与结果未知任务的文件。HTTP 取消不能保证 VoiceStudio 服务端已停止计算。聊天指令同样不自动重试。

## 管理接口与验证

- `GET /admin/voicestudio/voices?keyword=...`：音色列表，独立管理员认证。
- `POST /admin/voicestudio/voices`，`{config}`：校验并按草稿配置读取已保存音色，不保存插件；最多返回前 50 个已保存音色。工作台代理要求同源请求。
- `POST /admin/voicestudio/test`，参数为工具的合成参数：生成本地缓存，只返回文件编号和字节数，`sent:false`，不向 QQ 发送。
- `npm run voicestudio:export`：重新生成可导入插件 JSON。

回归覆盖模型先查音色再合成、一次独立 record 发送、缓存恢复、排队取消、失败不重复合成、未知工具拦截和凭据隔离。
