# 心绪 · 心理动力情绪插件

为Limen增加连续、有分寸的角色表达：开心时稍轻快，熟悉后稍亲近，遇到冲突会收敛，道歉后逐渐缓和。影响措辞、节奏与关注点，仍由当前 AI 模型生成具体回答。

## 理论与实现

弗洛伊德的结构模型把本我描述为寻求满足的驱力，把自我描述为面对现实、协调驱力与约束的机构，把超我描述为内化的规范与理想。参见 [Freud Museum 的结构模型说明](https://www.freud.org.uk/schools/resources/what-is-psychoanalysis-part-4-the-ego-the-id-and-the-superego/)。

本插件借用这一结构做角色表达设计，数值、公式和状态维度是工程方案，不是对心理理论的验证，也不用于评估用户的心理健康。

| 层次 | 工程映射 | 对回复的影响 |
| --- | --- | --- |
| 本我 | 亲近、表达、探索、自我维护四种驱动 | 为温暖、活泼、好奇、边界感提供动机 |
| 超我 | 对场景、责任、用户脆弱处境与明确表达要求的约束 | 该认真时收敛，避免失礼、玩笑过度或喧宾夺主 |
| 自我 | 综合信任、张力与调节能力，协调冲动和约束 | 情绪变化有上限，可逐步恢复、修复，并选择适合当前场景的表达 |

当冲突发生时，借鉴“升华”把攻击性转为建设性边界；放松时可使用轻微幽默，好奇时转为预期与计划。共情、自我整理是额外的工程表达策略。不会把投射、报复或情绪勒索作为拟人效果。

## 安装

更新源码后在原窗口按 `Ctrl+C` 退出旧进程，再重新启动项目。进入 **插件 → 插件概览 → 心绪 · 心理动力情绪**，点击“安装并配置”或“配置插件”，填写允许的好友/群聊并启用。也可从“插件 → 插件管理”的内置插件列表中安装。

也可以执行：

```powershell
npm run emotion:install
```

首次安装沿用当前 AI 好友与群聊白名单，有范围时启用。重复安装保留现有配置、范围、状态及开关；不会修改 AI 回复白名单。

```powershell
npm run emotion:export
```

生成 `dist/psychodynamic-emotion.plugin.json`，可导入已包含新执行层的Limen。插件包只包含默认配置，不包含用户状态。旧版本宿主需要先更新源码。

## 一轮对话如何处理

1. 仅在消息通过现有 AI 回复权限、准备开始生成时读取本人及当前人格的情绪状态。
2. 对旧状态按时间恢复，默认短期情绪半衰期 45 分钟，信任及熟悉感半衰期 14 天。没有等待消息也能恢复，读取时按实际经过时间计算。
3. 理解本轮是友好、喜悦、挫折、好奇、脆弱、敌意、修复或希望收敛的表达。默认混合模式先用本地规则，规则不确定时请求现有模型。输出只允许数值，不持久化原话、解释或推理。
4. 更新驱动和约束，协调为新的语气；每轮的情绪变化有上限，普通问候不会直接跳到极端亲密，用户难过时优先体贴。
5. 将本轮建议临时加入模型请求。真实输出仍服从当前人格、任务目标、回复过滤和工具权限；不会把情绪数值、内心争论或心理机制发给普通用户。

同一任务的状态更新与去重记录在一个事务中提交；生成失败后再次尝试会复用原建议，不反复累计。感知消息发生在生成前，所以即使最终发送失败，已经感知的这一轮状态也会保留。没有进入 AI 生成的消息不影响状态。

## 与记忆、群聊和人格配合

- 按机器人账号、会话、群内发言人、人格隔离，群里某人的语气不会改变机器人对另一个人的情绪状态。
- 若本轮流动记忆召回了本人资料，可增加很轻的熟悉感；不会把过去的冲突或悲伤再当成当前刺激，也不会把情绪数值写入长期记忆。
- 与 Chat Plus 同时启用时，使用心绪插件的语气建议，Chat Plus 继续控制参与、消息合并、输出过滤和自定义回复风格。
- 群聊合并时仅评估触发者的原始文字，不把其他成员的发言或共享群聊历史写入其状态。默认群聊仍需 @机器人；配合无 @ 的 Chat Plus 时，可关闭本插件的“群聊需要 @”。
- 网页试聊、主动话题、被固定屏蔽的群成员、指令及机器人自身消息不积累状态。无需启用 Agent，传统 AI 回复同样生效。
- `/new` 会清空当前会话内所有用户及人格的情绪状态；切换人格也会清空该会话的旧情绪，长期记忆继续保留。

本插件保存表达模拟状态，不声称 AI 具有真实意识、身体感受或线下生活，不让 AI 索取用户的情感照顾。最终语气效果受主模型和人格提示词影响。

## 管理指令

所有指令沿用 `BOT_ADMIN_IDS` 权限并要求匹配插件范围；管理员只能查看或重置本人在当前会话及人格下的状态。

| 指令 | 用途 |
| --- | --- |
| `/emotion help` | 查看说明 |
| `/emotion status` | 查看当前语气、调节策略、情绪维度、信任、熟悉度及三层协调量 |
| `/emotion preview 文本` | 用本地规则预览变化，不请求模型、不保存状态 |
| `/emotion reset` | 重置本人当前状态及熟悉感，保留长期记忆 |

插件管理的“模拟测试”也可以直接输入普通对话，预览本地规则下的结果。模拟使用默认初始状态，不读取真实用户状态，不写数据，也不请求模型。

## 调节风格

默认强调温暖和稳定；想更活泼可提高自然活泼程度，想更克制可降低表达强度、提高自我调节能力。用户明确要求严肃或直接时会进一步收敛。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `intensity` | `0.65` | 表达强度；0 关闭本插件本轮情绪处理 |
| `warmth` / `spontaneity` | `0.6` / `0.45` | 基础温暖及活泼程度 |
| `sensitivity` | `0.55` | 对当前情境的反应幅度 |
| `ego_strength` / `superego_strength` | `0.75` / `0.7` | 自我调节与场景约束；调低不会取消系统规则或权限 |
| `max_step` | `0.25` | 每轮情绪维度最大变化，0.05–0.5 |
| `recovery_minutes` | `45` | 情绪恢复半衰期 |
| `relationship_days` | `14` | 信任和熟悉感回归初始值的半衰期 |
| `memory_resonance` | `true` | 本轮召回记忆时轻微增加熟悉感 |
| `appraisal_mode` | `hybrid` | 混合情境理解；`rules` 关闭额外模型调用 |
| `appraisal_model` | 留空 | 同一 AI 服务上的情境理解模型；默认主模型 |
| `appraisal_timeout_ms` | `4000` | 可选模型判断超时，失败回退本地规则 |
| `appraisal_reasoning_effort` | 留空 | 留空沿用 AI 设置；服务支持时可单独配置 `none` 减少开销 |
| `retention_days` / `max_scopes` | `90` / `2000` | 状态保留与总量上限；到上限淘汰最久未更新的状态 |

混合模式可能为不明确的对话增加一次模型请求和等待；费用沿用配置的 AI 服务。接口失败、超时、非法 JSON、非数值或超范围结果均回退本地规则。规则模式对隐含情绪、讽刺和复杂否定的理解有限，可以通过模拟测试查看。

## 数据与验证

状态保存在 `DATA_DIR/bot.sqlite` 的 `emotion_states` 表，重试去重记录位于 `emotion_receipts`。不保存用户原文、模型判断理由或内部推理，日志只记录固定事件名。备份数据库即可保留状态。停用保留已有状态，删除插件会删除状态。

更新、停用、重置和人格切换会取消尚未完成的情境理解，旧请求不能在之后写回状态。恢复的旧任务不会再次刺激新装的插件；重试记录随对应任务过期清理。
