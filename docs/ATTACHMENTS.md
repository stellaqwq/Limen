# 图片与文件分析

启用[视频理解插件](VIDEO-ANALYSIS.md)后，网页附件还支持 MP4 / MOV / WebM / MKV 等视频，并通过 Agent 工具分段抽帧及可选音轨转写。附件仍遵守合计 10 MiB 限制，较大视频使用插件允许目录中的本地路径；QQ 视频需作为文件发送。

QQ 消息和网页“测试对话”使用同一附件处理流程。图片作为多模态输入交给当前模型；文档先在本机提取文字，再交给模型分析。原有 Agent 工具、语音输出概率、插件、发送防重、好友 / 群白名单和管理员指令规则继续生效。

## 怎么使用

- QQ 私聊：给机器人发送图片或文件，可以附带问题；只有附件时，默认描述图片或概括文档。群聊仍遵守群白名单和 `AI_GROUP_REQUIRE_AT`，默认需要在当前消息中 @ 机器人。
- 网页：顶部切换到“测试对话”，点击“添加图片或文件”，也可以拖入文件、在输入框粘贴图片。附件显示名称、大小和图片预览，可逐个移除；可以只发附件。试聊不会发送 QQ 消息，默认首页仍为机器人管理。
- 后续追问可以利用文档的历史摘录和模型此前的回答；如需重新查看图片细节或超出摘录的文档内容，请再次附上原附件。

## 格式和范围

| 格式 | 处理方式 |
| --- | --- |
| PNG、JPEG、WebP、GIF | 原图传给支持图片输入的模型；具体解码和动图支持取决于模型服务 |
| TXT、Markdown、CSV、TSV、JSON、JSONL、日志和常见代码文件 | UTF-8、带 BOM 的 UTF-16 或 GB18030 文字读取；按原始文本分析 |
| PDF | 提取前 N 页可选择的文字；默认 40 页。扫描版、图片表格、版面关系及 PDF 内嵌图片不做 OCR，需将相关页面作为图片发送 |
| DOCX | 提取正文、段落和表格内的文字；不执行宏，不提取页眉、页脚或嵌入图片 |
| XLSX | 最多 20 个工作表的单元格文字和缓存值，带工作表名、单元格地址；不执行公式，无缓存值时明确标记 |

旧版 DOC、XLS、压缩包、可执行文件及其他二进制格式不支持，需先转换。加密、损坏、解析超时或没有可提取文字的文件会明确提示；全部附件失败时不调用模型猜测内容，部分失败时会向模型标明未读附件。

每条消息最多 4 个附件，总大小不超过 `MEDIA_MAX_BYTES` 且最多 10 MiB。上传接口同样校验实际内容和编码。文档单条消息合计最多提取 24000 字符，超出时明确标记截断。每次文档解析使用独立 Node 进程、192 MiB JavaScript 堆上限和 20 秒超时，不向解析进程传递机器人密钥环境变量。

管理台“全部设置 → AI 与回复”提供：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `AI_VISION_ENABLED` | true | 开启图片输入；需要当前模型支持视觉 |
| `AI_ATTACHMENT_MAX_CHARS` | 24000 | 单条消息全部文档提取文字的合计上限，1000–100000 |
| `AI_PDF_MAX_PAGES` | 40 | 单个 PDF 读取的前 N 页，1–200 |

本次保留现有 `high` 推理和模型参数。代码更新后需关闭原启动窗口，重新运行 `start.cmd` 完整重启进程；以后修改以上运行设置也需重启生效。

## 缓存与恢复

- QQ 文件通过 QQNT 媒体下载接口取得，确认下载回调、大小与可用 MD5 后才发布文件消息；文件不完整、过大或下载失败时不会产生虚假的可用路径。文件缓存位于 `QQ_KERNEL_DATA/file-inbox`，按 `MEDIA_CACHE_DAYS` 清理。
- 网页附件只接受上传内容，生成随机编号后存入 `DATA_DIR/agent-attachments`，不能通过接口指定任意磁盘路径。管理员认证和网页同源检查继续适用。附件只可绑定一个任务，重复提交不能再次绑定同一附件。
- 附件绑定持久化，可在服务重启后继续处理。网页未发送的附件（包括从输入框移除的待发送文件）在一天后清理；任务附件在对应任务按历史保留策略删除后清理。清理在启动和定时维护时执行。
- 聊天历史保存有界文档摘录（每个文档最多约 4000 字符、单任务合计最多 8000）和图片名称提示，不把图片 Base64 放入历史上下文。附件正文不写入日志；管理台会话只返回附件名称、类型和大小。

解析器接口依据 [pdf-parse 官方项目](https://github.com/mehmet-kozan/pdf-parse)、[fflate 官方项目](https://github.com/101arrowz/fflate) 和 [fast-xml-parser 官方项目](https://github.com/NaturalIntelligence/fast-xml-parser)；QQNT 媒体下载参数参考 [NapCat 的 QQNT 接口定义](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-core/services/NodeIKernelMsgService.ts)。
