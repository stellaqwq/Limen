# 群聊上下文感知

机器人回复时可以参考同群近期聊天，包括未 @机器人的消息、机器人自己的发言、发言人的 QQ 号 / 群名片 / 昵称、@ 对象和引用消息。只在现有 AI 群白名单中生效，原有“需要 @机器人”以及管理员指令权限继续生效，不会因为记录背景而主动回复每条消息。

例如，小红先说“大家晚上六点见”，另一位成员稍后 @机器人问“刚才说几点见？”，模型会收到前面的群聊记录及各自的发言人，能够据此理解提问。多人同名时按 QQ 号区分；背景不足时应询问，不编造缺失的消息。

## 启用与配置

在“全部设置 → 回复范围”填写允许回复的群号，在“AI 与回复”管理群聊上下文感知。保存后重启机器人生效。默认开启此能力，但群白名单为空时不记录任何群聊背景；不会自动扩大回复范围。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `AI_GROUP_CONTEXT_ENABLED` | `true` | 群聊上下文开关；关闭后停用并清除背景缓存 |
| `AI_GROUP_CONTEXT_MESSAGES` | `30` | 每次最多参考的近期消息数，范围 1–200 |
| `AI_GROUP_CONTEXT_TTL_MS` | `900000` | 背景消息有效期，默认 15 分钟，范围 1000–86400000 毫秒 |
| `AI_GROUP_CONTEXT_MAX_CHARS` | `8000` | 每次附加背景的字符上限，范围 1000–32000；与当前问题长度和 AI 问答轮数独立 |

每条背景消息最多保留 1000 个字符，超出会截断。每群缓存最多为“消息数上限 + 当前消息”条；输入模型时再按总长度取舍。近期消息按接收顺序排列，不会把当前提问之后才到达的群聊塞进该问题的背景。重复事件和内核自身消息回声会去重。

引用仅从当前账号、当前群的有效缓存中解析。找不到或过期时明确标记不可用，不跨群或跨账号读取。图片、文件、语音只记为占位，不把文件路径、Base64 或附件正文复制到群聊背景中；当前问题所附的图片 / 文档继续走原有多模态分析流程。

## 新对话与保留

管理员 `/new` 会同时清空当前会话的 AI 问答上下文和近期群聊缓存，保留人格及显式记忆。网页管理的“清空上下文”、应用人格及删除绑定人格也清空对应缓存。正在执行或待核对任务时，`/new` 仍提示先处理任务。

近期背景单独保存在本地 SQLite 的 `group_context_messages` 表中，重启后可在有效期内继续使用。启动、收取消息、取用背景和定期维护时清理过期记录；超过有效期的内容不会提供给模型。移出群白名单或关闭 AI 后，启动或维护时会清除对应背景。

此缓存独立于忽略任务正文的保留开关：即使 `RETAIN_IGNORED_JOB_CONTENT=false`，开启群聊上下文时仍会缓存白名单群的未 @ 消息，受上述独立条数、时限与长度限制。机器人已经参与的问答仍按 `AI_CONTEXT_TURNS` 和历史保留策略管理；背景有效期不改变既有问答历史。

群聊正文、昵称和引用均作为不可信背景放在当前用户消息中，不进入系统规则或工具权限。只有消息实际发送人和原有配置决定管理员、记忆与插件权限。该功能兼容 Agent 与传统 AI 回复，不为私聊或网页会话附加群消息，也不在运行日志中输出背景正文。
