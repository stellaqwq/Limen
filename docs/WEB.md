# Web 管理台

在项目根目录运行 `npm run launch` 或双击 `start.cmd`。启动窗口会打印随机本机端口与访问路径。Web 端只监听 `127.0.0.1`；OneBot 的 HOST/PORT 设置仅作用于机器人接口。

## 默认控制台（新版）

桌面版启动后进入新版控制台（`<prefix>/console`），源码在 `src/web/console/`；`npm run launch` 打印并打开的也是这个地址。浏览器直接打开根地址仍是经典管理台，保留给启动动画与既有自动化，不再作为日常入口。

新版控制台按 limen-console 的信息架构重做，**页面不包含任何演示夹具**：账号、配置、任务、消息、插件、记忆与空间记录全部来自正在运行的服务；接口失败时显示错误与重试，读到空列表时显示空状态，不用样例数字顶替。

- 路由为 hash 形式：`#/config/ai`、`#/providers`、`#/platforms`、`#/plugins`、`#/plugins/<kind>`、`#/dashboard`、`#/chat`、`#/data/messages|jobs|logs`、`#/qzone`、`#/settings`。
- `src/web/login-server.mjs` 在同一随机登录前缀下提供静态文件：`<prefix>/assets/*` 与 `<prefix>/console/*`；页面由服务端注入 `limen-api-base` 与 `limen-embedded`，前端直接请求同源接口，不需要额外代理。**没有使用 `<base>`**，避免页面内的 hash 链接被解析回经典管理台。
- 该路由使用独立 CSP（`script-src 'self'`），页面不含内联脚本；旧管理台的 nonce CSP 保持不变。
- 数据层在 `src/web/console/assets/api.js`：读取 `/state`、`/settings`、`/plugins`、`/jobs`、`/job-conversations`、`/telemetry`、`/qzone/status`、`/qzone/posts`、`/agent`，插件详情与专属面板按需读取。每个接口单独记录成功或失败，页面按区块渲染。
- 账号与群号在页面上统一脱敏；密钥不回显，配置页只提交改动过的键。
- 写操作接入真实接口：保存配置（带 `revision`）、查看密钥、读取模型、插件启停 / 配置保存 / 作用范围 / 安装 / 删除、任务核对、扫码与退出、重启、空间草稿生成 / 编辑 / 发布 / 核对、网页试聊。
- 插件配置页的“作用范围”决定插件处理哪些私聊与群聊，以及群聊是否需要 @机器人；启用前必须至少设置一个范围。插件配置表单由插件自己的 `config_schema` 生成，没有 schema 时提供 JSON 编辑器。
- 侧栏不再提供「经典管理台」入口；`<prefix>/legacy` 仍可访问，仅用于兼容与排障。
- 界面约定（`assets/styles.css`）：一个页面只有一层带边框的容器（`.panel`），页面内的分区用浅灰分区条（`.sec-head`）+ 分隔线切分，不再为每个分区套一张卡片；间距统一取 `--sp-1..6`（4/8/12/16/20/24），不要在样式里写 13/14/18/22 这类一次性数值；表单为两列、标签在控件上方；提示条固定在右下角，不遮挡正文；深色主题沿用同一套语义变量，新增样式只用变量、不写死颜色。
- 说明文字由 `app.js` 顶部的 `HINTS` 开关统一控制，当前为 `false`：页头说明、分区说明、卡片说明、字段帮助一律不渲染，界面只留标题、数据与控件。三类文字不受开关影响——错误与告警、空状态引导、危险操作提示；配置项的取值规则改成标签后缀（`FIELD_RULE`）或占位符（`FIELD_PLACEHOLDER`），例如「上下文轮数（-1 全部，0 不保留）」，所以关掉说明后仍知道怎么填。需要恢复说明时把 `HINTS` 改回 `true` 即可。
- 验收：`node scripts/console-frontend-qa.mjs`——直接启动真实 `createLoginServer`，用回放后端检查默认入口、静态资源、CSP、真实数据映射、写入、全部路由、五档视口与深色主题，不连接 QQ、不改 `.env`。

## 经典管理台主页与测试对话

经典管理台默认进入“机器人运行概览”，先查看 QQ 连接、AI 回复开关和任务状态。导航按“机器人管理、内容与运行、配置”分组，原有登录、消息、插件、图库、空间、日志、任务和设置入口均保留。

“Agent 管理”分为“会话与记忆”“人格配置”“工具与执行”三个页签。直接与 Agent 对话默认隐藏，点击顶部“测试对话”才进入测试界面，点击“返回管理”回到此前页面。手机上使用顶部对话图标切换，导航收进菜单按钮。

测试对话可用 Enter 发送，Shift+Enter 换行；输入中文时的候选确认不会触发发送。测试消息不会发到 QQ，工具范围与具体使用说明见 [Agent](AGENT.md)。

已保存的记忆可在“Agent 管理 → 会话与记忆”中选择会话后逐条编辑：点击“编辑”，修改名称和正文，再点“保存记忆”。保存后用于后续任务，取消可放弃草稿。名称最多 60 字符、内容最多 500 字符；群聊按成员 QQ 区分，编辑时暂时锁定会话选择。自动刷新保留草稿，并发更新会提示冲突，详细行为见 [人格与会话记忆](AGENT.md#人格与会话记忆)。

流式输出默认开启，测试对话通过 SSE 实时显示模型正文，推理内容不会显示。连接断开时自动重连，并保留轮询作为补充；查看较早内容时不会强制滚回底部。可在“全部设置 → AI 与回复”关闭流式输出或修改 QQ 分段长度，保存后重启生效。

## 源码包首次启动

先运行 `npm ci`。源码包不包含 QQ 官方运行时，宿主清单 `runtime/kernel/adapter.json` 是本机生成文件，不需要手工创建。首次启动默认从 QQ 官方下载：启动入口读取官网发布配置、下载安装包、校验腾讯签名后解包并构建桥接，因此需要预先安装 7-Zip（不在默认位置时设置 `QQ_7ZIP`）。下载失败时会回退到本机已安装的 QQ；本机也没有可用 QQ 时，按提示运行 `npm run qq:prepare -- --from "实际 QQ.exe 完整路径"`，或安装 7-Zip 后运行 `npm run qq:download -- --prepare --activate`，再启动工作台。不想联网下载时，把 `QQ_RUNTIME_SOURCE` 设为 `local`，启动入口会直接复制本机已安装的 QQ。

已有运行时但缺失宿主、项目被移动或 Node.js 被更换时，启动入口会重新生成对应宿主。配置与账号数据不会被重置。只体验界面可运行 `npm run launch -- --demo`。

## 设置与生效

“全部设置”覆盖 `src/config.mjs` 中全部运行参数，以及 QQ 下载解包使用的 `QQ_7ZIP`。分为 AI 与回复、Agent 执行、回复范围、QQ 与运行时、OneBot 与推送、队列与发送、数据与保留、实验驱动八组。顶部和设置内搜索支持中文名称、说明和环境变量名。

图片大小与发送超时位于“QQ 与运行时”，图片缓存保留位于“数据与保留”，Base64 大图需要的请求上限位于“OneBot 与推送”。图片与 AstrBot 表情插件的详细配置见 [图片发送](IMAGES.md)。

“AI 与回复”还可设置群聊上下文感知、近期消息条数、有效期和背景长度上限。它仅作用于 AI 群白名单，独立缓存未 @ 的近期消息，保留策略见 [群聊上下文感知](GROUP-CONTEXT.md)。

同组提供两个默认开启的独立开关：“群聊回复时 @发送人”（`REPLY_AT_SENDER`）和“回复时引用原消息”（`REPLY_QUOTE_MESSAGE`）。适用于普通 AI、Chat Plus、消息插件和管理员指令回复，流式各段也遵循设置。私聊不会 @，引用开关同时控制私聊与群聊。语音仍独立发送，定时主动聊天不 @ 或引用旧用户消息。保存后点击“重启生效”。这两个选项只调整回复样式，不改变“群聊仅在被 @ 时回复”的触发条件。

“过滤 AI 回复中的 Emoji”（`AI_STRIP_EMOJI`）默认开启，由程序在发送前删除 Unicode 表情，包括肤色、旗帜、键帽及 ZWJ 组合。按完整字符簇处理，并在流式中保留尚未完整的键帽 / 代理对，避免分段漏发；数字、中文、普通标点和代码保留。规则覆盖普通 AI、Agent、Chat Plus、网页试聊和 AI 语音工具的合成文本。过滤后的正文用于任务详情和后续问答历史；若只剩空白，任务标记为忽略，原因是“AI 回复过滤 Emoji 后无可发送正文”，不发送空白或只有 @、引用的消息。保存后重启生效。

此设置处理 AI 输出的 Unicode 字符，消息插件的固定回复、QQ 原生表情段和表情包图片按各自配置发送。过滤器不修改用户输入；被忽略任务的正文仍遵循保留策略，未保留时网页显示“消息正文未保留。”。重启时会过滤已有待发送任务尚未发送的正文；已确认送达的流式分段记录保留，以免重发。字符识别采用 Node.js 自带的 Unicode 属性与字符簇分段，组合规则参考 [Unicode Emoji 标准](https://www.unicode.org/reports/tr51/)。

1. 设置模型基础地址（如 `http://127.0.0.1:11434/v1`）、模型标识及 API Key。“读取可用模型”调用服务的 `/models`；不支持该接口时可以直接手填模型标识。
2. 在回复范围中设置好友或群白名单，再启用 AI。群聊默认要求 @机器人。
3. 点击“保存设置”。服务会校验完整配置并原子写入 `.env`，提示等待重启。保存失败不会写入部分配置。
4. 点击“重启生效”。安全关闭旧服务后使用新配置启动；页面及访问路径保持可用。新配置无法启动时尝试恢复原服务，已保存的配置仍保留，便于继续修正。

未保存的修改会保留到切换分组之后；“重新加载”可放弃修改。多窗口使用同一份配置时，旧版本的保存会被拒绝，需重新加载后再编辑。启动环境变量覆盖的字段不可在页面修改。

复用其他进程的服务时，工作台可以查看和保存配置，不能替原进程重启，请在原启动窗口停止后重新运行。`npm run start` 配合 `npm run login` 也属于此情况。外部服务重启并修改管理员 Token 后，重新运行 `npm run login` 或 `npm run launch` 生成新的工作台连接。

演示模式 `npm run launch -- --demo` 使用独立临时配置，不写真实 `.env`，不登录 QQ、不发送真实消息，退出后清理。

### 固定屏蔽群成员

在“全部设置 → 回复范围 → 固定屏蔽群成员消息”填写规则，每行一条（也支持逗号分隔），最多 500 条。下列号码仅为格式示例：

```text
1036914541:123456789
*:987654321
```

第一条仅屏蔽该成员在指定群的消息；第二条屏蔽该成员在所有群的消息。保存后点击“重启生效”。规则持久保存在 `.env` 的 `GROUP_BLOCKED_USERS` 中，`/new` 和群聊增强的上下文重置不会删除规则。移除对应行并保存、重启即可解除屏蔽。

屏蔽优先于 @触发、管理员身份和插件：消息不会触发 AI、消息插件、群聊增强参与判断、管理员指令或后台识图，也不会进入近期群聊背景；启动时清理该成员已有的近期群聊背景缓存，引用这些旧消息时仅显示来源不可用。队列中的旧回复执行前也会重新检查规则。私聊和其他未命中规则的群不受影响。

“运行监控 → 任务队列”会显示“群聊发送人命中固定屏蔽规则”。正文仍遵循“保留忽略任务正文”设置；消息监听和 OneBot 事件推送继续显示/转发收到的事件，规则不会撤回 QQ 消息。既有问答历史和已保存的长期记忆不会被此设置删除；需要清空当前会话上下文时可由未屏蔽的管理员使用 `/new`。

## 密钥与配置文件

密钥默认不返回到页面。可主动“查看已有密钥”、修改、生成随机值或清空。OneBot 和管理员 Token 必须独立且不少于 24 字符。`SESSION_KEY` 为 64 位十六进制；更换后原加密会话无法读取，需要重新扫码。

“导出配置”生成不含密钥的 JSON。导入只填充非密钥字段，不会立即保存或重启。已有密钥只在明确修改后提交；显式“清空此项”会在保存后删除该值。不要把管理员 Token 提供给 OneBot 插件。

提示词支持多行和混合引号。若值无法直接用 dotenv 引号表示，保存时自动使用 `qqai-base64:v1:` 编码，机器人读取时还原原文；这是文件转义格式，不是加密，页面与配置导出仍显示原文。

## 运行监控

侧栏“运行监控”将“消息监听 / 任务队列 / 运行日志”合并在同一页，点击页内标签切换。各标签保留自己的筛选条件、暂停状态和已展开的消息或任务详情。标签支持左右方向键及 Home / End，手机上也可直接切换。

概览中的接收消息、检查任务队列和查看日志会打开对应标签。地址分别为 `#monitor/messages`、`#monitor/jobs`、`#monitor/logs`，可直接访问或刷新，也支持浏览器前进和后退；旧版的 `#messages`、`#jobs`、`#logs` 自动转到对应标签。离开后再次点击侧栏“运行监控”，回到本次页面中上次查看的标签。

### 消息监听

展示实际接收的私聊、群聊消息，以及通过机器人发送并得到确认的消息；即使 AI 未启用或发送者不在白名单，也可以观察接收消息。支持按会话类型、收发方向、正文和 QQ/群号筛选，展开原始事件、暂停显示、清空当前显示和导出 JSON。

页面每 1.5 秒增量读取事件；切到后台时暂停页面轮询，回到页面后补读。记录属于进程内临时历史，最多保存最近 1000 条运行事件，机器人进程退出后清空。大量事件超过容量时，较早的记录会被淘汰。暂停只冻结显示，后台仍接收消息；清空显示不删除 QQ 消息或数据库记录。

消息行按事件 ID 复用；展开的“原始事件”不会因新消息插入而收起，键盘焦点也保留。筛选后再显示同一条消息会恢复展开状态。手机上的会话类型与消息方向有独立标签，保留完整选项宽度。

消息正文使用纯文本展示，不执行 HTML；图片消息段展示为类型及可展开的元数据，Base64 原始图片不会写入监听缓冲区。媒体、群管理等能力范围以 README 中的实机验证表为准。

### 运行日志与任务

运行日志记录连接状态、服务启动、配置保存、AI 排队、生成失败、发送确认、推送错误等事件，支持级别和关键词筛选、暂停、清空显示、导出。日志只允许诊断字段，不记录正文、API Key 或接口凭据。消息内容在同页的“消息监听”标签读取。

任务队列自动展示最近 50 项任务及生成/发送尝试次数。展开“查看消息与回复”可核对会话、输入和回复。“结果未知”表示消息可能已经送达，应先到 QQ 中核对，再标记“已核实发送”或“放弃任务”，不会提供自动重发以免重复发送。

顶部“会话”下拉框可只看某个群聊、私聊或网页试聊的任务；群聊和私聊同时显示机器人账号，区分不同账号下相同的群号或 QQ 号。会话选项来自保留中的全部任务，选择后先按会话查询，再取该会话最新 50 项，不会被其他群的新消息挤出。原有“任务状态”继续在显示的最新 50 项中筛选。自动更新、手动刷新或切换监控标签均保留当前选择，选择“全部会话”恢复全局列表。加载失败时可点击“刷新队列”重试，快速切换会话不会被旧请求覆盖。

Chat Plus 进入 AI 读空气后，会将简短判断理由保存在对应任务中。“查看消息与回复”可查看参与结论、理由、置信度及门槛，区分模型认为不适合参与和置信度不足。失败或没有理由时明确显示对应说明；理由不作为 QQ 回复发送。旧版任务未保存的理由无法补回。

等待任务会按有效期自动转为“失败 / expired”，关闭 AI 或 QQ 离线时仍会处理；正在执行及发送结果未知的任务不会被等待超期流程改写。

“数据与保留 → 保留忽略任务正文”默认关闭。关闭后，新 ignored 任务只保存防重和身份信息；下次启动会脱敏既有 ignored 任务的原始事件、输入和回复正文，无法恢复。开启时按“消息与历史保留”天数保存全文。此开关不控制 OneBot 查询缓存，也不控制 QQ 官方 SDK 或 AstrBot 数据；未回复的消息仍可能保存在这些独立数据层。详见 README“未回复消息如何保存”。

任务详情分别显示处理原因与正文去向：白名单外过滤、正文未记录、正文已脱敏且不可恢复、原消息没有文本，以及旧记录无法确认的内容状态。重新开启保留不会恢复旧正文；字段下方与重启确认框均有明确提示。

真实脱敏会在同一数据库事务中写入 `privacy_audit`，保存时间、改写条数和执行环节，不记录正文、昵称、附件或凭据；同时输出 `ignored_job_content_redacted` 运行日志。“任务队列 → 正文脱敏记录”展示持久记录及累计改写数量，重启后仍可查，幂等检查不会重复产生记录。旧版本未记录的操作不能追溯。新消息只保存防重信息时标为“正文未记录”，不伪造为一次删除操作。

三个监控标签分别说明“内存按条”和“磁盘按天”的范围，并链接到“数据与保留”。页面缓冲由消息与日志共享最多 1000 条，服务进程退出后清空；数据库任务、上下文和 OneBot 查询缓存按当前运行的 `HISTORY_RETENTION_DAYS` 清理。审计表只长期保存上述操作元数据，页面显示最近 10 次，不属于消息正文缓存。

## 验证与源码

“OneBot 与推送”中的“图片访问地址”用于跨主机或容器取图；同机留空自动选择本机地址。QQ 原始图片会先下载，再通过仅授权对应图片的链接提供给 AstrBot。“数据与保留”的图片缓存天数同时控制收发缓存。接收、历史图片回读与访问范围见 [IMAGES.md](IMAGES.md)。

`npm test` 运行全部回归；`npm run check` 检查模块语法；`npm run web:qa` 使用本机 Chrome 的隐藏窗口验证管理台，包含响应式布局和实际交互。可通过 `CHROME_PATH` 指定 Chrome 路径。截图和报告写入 `.impeccable/review/`，全部使用带标记的模拟数据。

`npm run source:export -- <新目录>` 导出源码及 SHA-256 清单，包含 Web 源码、测试、产品与设计文档，不包含真实 `.env`、账号数据、运行时、依赖或截图。首次在新目录运行时，先 `npm ci`、`npm run init`，再按 README 准备官方 QQ 运行时。
## 插件管理

左侧统一进入“插件”。“插件概览”显示真实安装与启用状态，并集中放置群聊增强、表情图库、流动记忆的专属页面，以及心绪和 VoiceStudio 的配置入口。这些页面通过页内导航切换；原有 `#plugins`、`#groupchat`、`#memes` 链接继续有效。

“插件 → 流动记忆”（`#memory`）以可旋转缩放的 3D 神经网络展示真实记忆，每条记忆对应一条连接；新建、编辑、归档、恢复、删除和筛选同步更新图谱及列表。会话与人格分别选择，插件停用时仍可维护数据。无需 Embedding 配置，浏览器不支持 WebGL 时使用完整列表管理。详见 [流动记忆](LIVING-MEMORY.md)。`npm run memory:qa` 验证真实 WebGL 和六种响应式宽度。

进入“插件 → 插件管理”可新建或导入 JavaScript 消息插件、编辑 JSON 配置、设置好友与群聊范围、优先级和执行时限，查看执行统计并即时启停。模拟测试预览当前草稿的结果，不通过机器人发送 QQ 消息。新建与导入后的插件默认停用。概览中的“安装并配置”只安装并打开编辑器，不自动启用。切换子页保留草稿，打开其他插件前仍会确认是否替换未保存内容。详见 [自定义插件](PLUGINS.md)。

`npm run plugins:qa` 使用隐藏 Chrome 检查插件的新建、编辑、启停、导入删除、预览、超时、冲突和响应式布局。截图与报告保存在 `.impeccable/review/plugins/`，全部使用模拟数据。
